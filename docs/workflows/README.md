# Workflows

Business behavior organized around the work people do in Merit. These pages
explain current capabilities, their rules, and their limits. Start with the
[grantmaking overview](review-and-decide.md) for the relationship between tasks
and the permissions and guarantees they share.

| Task                                                      | Read                                                  |
| --------------------------------------------------------- | ----------------------------------------------------- |
| Set purpose, budget, criteria, and responsibility         | [Prepare a round](prepare-round.md)                   |
| Record received material, readiness, and revisions        | [Record applications](record-applications.md)         |
| Track requested work and received judgments               | [Request and record reviews](review-applications.md)  |
| Accept an invitation and submit an independent assessment | [Participate in a review](participate-in-review.md)   |
| Propose funding and understand budget effects             | [Recommend funding](recommend-funding.md)             |
| Maintain shared applicant and reviewer profiles           | [Manage contacts](manage-contacts.md)                 |
| Explore the demo and request workspace access             | [Public demo and access](public-demo-and-access.md)   |
| Create organizations and invite their first owners        | [Provision organizations](provision-organizations.md) |
| Manage membership, grant access, and invitations          | [Manage a team](manage-team.md)                       |

[Future committee design](committee-decisions.md) covers unimplemented reviewer
discussion, briefs, publication, and decisions. It is separate from the current
workflows above; GitHub issues and milestones own delivery scope and sequencing.
