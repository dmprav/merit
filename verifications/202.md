# Verification record

## Checks run

- `pnpm install` with the pinned pnpm 12.18.0 updated `pnpm-lock.yaml` for
  `@fontsource-variable/instrument-sans@5.3.0`, and `pnpm install --frozen-lockfile`
  then passed.
- Checked that every shared style reads the family through `--font-sans`: `base.css`, `tooltip.module.css` and the sign-in page do; email layout keeps its own platform stack on purpose.
- Ran the public demo on Chromium at 1440×900 and captured the applications
  list, the round applications table and an application detail page, each with
  Instrument Sans and with the previous platform stack. Instrument Sans loaded
  from the app on every page, and each page truncated the same elements in both
  versions.
- Measured at 13px: with `tabular-nums`, "1111" and "8888" were both 31.20px
  wide. A sample applicant line was 411.7px in Instrument Sans and 400.3px in
  Liberation Sans, which has Arial's widths, so the Typeface section no longer
  claims the font is narrow.
- `vp run check:docs` and `vp check --deny-warnings`: passed.
- Regenerated the 20 Linux visual baselines with
  `vp run test:browser:stories:all visual.spec.ts --project desktop --project mobile --update-snapshots`
  in the CI image `mcr.microsoft.com/playwright:v1.64.1-noble`, then reran
  without `--update-snapshots`: 20 passed. Compared every changed baseline with
  its previous version: the changes are the new letterforms and the reflow from
  wider text, such as "Delete draft" moving to the next row in the focus story
  and the reading measure widening, because `ch` follows the font's zero.
  Instrument Sans's word space is narrower (2.6px against Inter's 3.7px at 13px),
  so small bold text looks tighter in the 1× mobile baselines.
