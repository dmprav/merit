# Verification record

## Behavioral decisions

- Decisions require a reason, "Decided by" (up to 200 characters), and a decision date that is not after today; the date check reuses the UTC+14 bound from withdrawals. Conditions, required only for Fund with conditions, are capped at 5,000 characters.
- Every version after the first requires a change explanation, which applies to both corrections and later decisions after a Defer. A save that changes nothing records no version, needs no explanation, and shows "No changes to record".
- The first decision is prefilled from the current recommendation (`Fund with a condition` → `Fund with conditions`), otherwise it defaults to Fund with empty fields.
- Fund and Fund with conditions are rejected when the round has no budget (`budget_required`) or when committed funding would exceed the budget (`commitment_exceeds_budget`). Budget changes below the committed total are rejected (`budget_below_commitments`). Decision saves and budget edits take the round row lock, so concurrent saves can't over-commit.
- Withdrawing a funded application is rejected (`application_has_commitment`). The web dialog opens as an explanation with a single Close action instead of the form. Any decision hides Delete and blocks it on the server.
- The demo seeds a €24,000 Fund decision dated at seed time, validated through the decision rules.
- The Decision column is added to the round's application list only, not the workspace Applications list. The MCP tool takes flat fields (`outcome`, `amount`, …).
- Pack linkage (#45) is excluded by the requester.
