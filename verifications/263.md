# Verification record

## Behavioral decisions

- Tooling CLIs parse their arguments strictly: unknown flags, missing values and malformed numbers (such as `queue claim 12abc` or `--pr 7abc`) now fail with the command's usage instead of being ignored or truncated. This includes `pr-review-packet.ts` and `pr-screenshots.ts`, which main added.
- `GH_REPO` must name a github.com repository; other hosts and proxy-shaped URLs are rejected.
- Agent tooling reaches GitHub only through REST `gh api --hostname github.com` calls in `tooling/agents/github.ts`, so neither `GH_HOST` nor `gh`'s default host can redirect them.
- A fail-fast file lock that finds the lock busy retries once if the holder released it mid-inspection, and otherwise names the holder it saw.
- `ui:verify` writes `results.json` schema version 2, where each target is `audited` or `errored`, and an interrupted run no longer writes results after teardown releases the output.
- `ledger summary --json` returns decisions as structured entries rather than preformatted bullets; text output is unchanged.
- `worktree` commands print their warnings on stderr after the operation finishes, before the summary, and omit them from `--json` output.
- The React Compiler check now fails when it finds zero files to compile; its reporting is otherwise unchanged.
