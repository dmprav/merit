# Verification record

## Behavioral decisions

- Clean required recorded creation before issuing a database drop. It preserved databases for reused names, skipped creation and unregistered slugs.
- An offline clean retained the branch and registry record for the next cleanup attempt. Clean consumed ownership before issuing a drop so an interrupted request could not authorize a second drop.
- Registered worktree resets recorded a successfully recreated database before migration or seeding. An interruption between PostgreSQL creation and the registry write left the database for manual inspection.

## Checks run

- `pnpm exec vp test run tooling/agents/worktree/clean.test.ts -t 'preserves a database that existed before create'` failed on the original code. The drop adapter received `merit_existing` once while the registry held `databaseCreated: false`. The same test passed with the fix.
- The reset regression failed before the fix with the registry still recording false after successful recreation. The two reset suites passed all 24 cases after the fix.
- `vp run test:agents` passed 635 tests with three skipped. The app build, code, documentation, complexity, architecture and staged secret checks passed.
- The fixed CLI cleaned the temporary worker checkout created with `--no-db`. It removed its Git resources and reported its database as skipped.
- The independent review found retry hazards after an ambiguous rollback drop and an offline clean of a custom branch. Both cases received regression tests. CodeRabbit also identified the rollback case and prompted an assertion on the exact database and admin URL passed to reset.
- After merging #315, the agent tooling suite passed 637 tests with three skipped, the reset suite passed all 18 tests, and code and documentation checks passed. The combined retry cases verified that recovery preserved the branch and only dropped a database with recorded ownership.
