# Verification record

## Behavioral decisions

- A detached command's process group counts as stopped only when no member is left. Its leader's exit proves nothing.
- `runCommandAsync` stops the group after every exit. After a successful exit, a group that survives SIGKILL fails the command instead of only being logged at teardown.
- On Linux, a member counts only while it shares the group's session and has not exited. A zombie holds no ports or pipes, and in a container whose PID 1 never reaps orphans it would otherwise hold every teardown to the full grace period and report a failed cleanup.
- Once the leader has exited, a live process with its pid means the group emptied and the pid was reassigned, so the stop signals nothing. This keeps the old guard against signalling a reused pid, for example a server whose group died mid-run.
- A group that still has a member after SIGKILL makes the stop reject, so the cleanup stack logs the failure.

## Checks run

- On the original `processes.ts`, with only the new export name aliased, three new tests failed in `vp test tooling/storybook/ui-verify/processes.test.ts`, each because the descendant was still running. They cover a wrapper's failed exit, a server that exited early, and a wrapper that exits on SIGTERM while its descendant ignores it.
- On the first-round fix, the pid-reuse test failed because the stop killed the process holding the reused pid.
- With the fix, the focused tests passed three times in a row in about 2 seconds. `vp run test:agents` passed all 583 tests, including the new `/proc` stat parser tests and the file-lock tests that now use the shared parser.
- `check:code`, `architecture` (after building the app), and `code-health` passed.
- `vp run ui:verify --story "*button*" --viewport desktop` built Storybook, served and audited 19 stories, logged no cleanup failure, and left no Storybook or Vite process running. One story, `components-button--aligned-at-end`, failed its horizontal overflow check (1445px against 1440px), which this change does not touch.

## Could not verify

- macOS, where the probe uses `kill(-pgid, 0)` instead of `/proc`: the environment is Linux only.

## Did not verify

- App-server targets with `--route`: they need the Compose Postgres service, which this environment does not run. They use the same `stopProcessGroup` as the Storybook server.
- An end-to-end test that a zombie does not keep a group alive. It needs a non-reaping parent inside the group's session, so the parser's state check is unit-tested instead, and this container's PID 1 exercised the rule in the integration tests.

## Dismissed review findings

None. The independent review's six findings were all fixed: pid reuse after the group emptied, a five-second test, a third copy of the `/proc` stat parser, read errors counted as exited, host-dependent zombie coverage, and a swallowed stop failure after a successful command. CodeQL's code-construction alert on the test helper was fixed by passing values to fixed scripts as arguments.
