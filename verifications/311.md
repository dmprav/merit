# Verification record

## Behavioral decisions

- A detached command's process group counts as stopped only when no member is left. Its leader's exit proves nothing.
- `runCommandAsync` stops the group after every exit. After a successful exit, a group that survives SIGKILL fails the command instead of only being logged at teardown. A server whose readiness fails still reports its readiness error when the stop fails too.
- On Linux, a member counts only while it shares the group's session and has not exited. A zombie holds no ports or pipes, and in a container whose PID 1 never reaps orphans it would otherwise hold every teardown to the full grace period and report a failed cleanup. A zombie whose other threads still run counts, as does a `/proc` entry that cannot be read and a `/proc` that cannot be listed, so the group is still signalled.
- When a group still exists but has only exited members, it gets one SIGKILL. A member forked after the `/proc` listing would otherwise be missed, and a group signal reaches every member. A group that no longer exists is not signalled.
- Reading the group when its leader exits never throws out of the exit listener, so a failure there cannot end the run before teardown.
- Once the leader has exited, a live process with its pid means the group emptied and the pid was reassigned, so the stop signals nothing. A group that is already empty when its leader exits is recorded, and later stops never signal it.
- A group with live members is not stopped when its leader exits mid-run. That would end a server whose wrapper hands off to it and exits.
- This PR is not an autonomous `agent:pr`, so the protected-path policy does not gate it. It touches `tooling/agents/` only to share the `/proc/<pid>/stat` parser with the file lock, as the independent review asked.

## Checks run

- On the original `processes.ts`, with only the new export name aliased, three new tests failed in `vp test tooling/storybook/ui-verify/processes.test.ts`, each because the descendant was still running. They cover a wrapper's failed exit, a server that exited early, and a wrapper that exits on SIGTERM while its descendant ignores it.
- On the first-round fix, the pid-reuse test failed because the stop killed the process holding the reused pid.
- Mutation checks each failed a test: removing the stop after a successful command, counting zombies as live (including a deterministic zombie built with `sh` and `setsid`), and dropping the session check.
- With the fix, the focused tests passed three times in a row in about 2 seconds. `vp run test:agents` passed all 592 tests, including the `/proc` stat parser, reader, and thread tests and the file-lock tests that use the shared parser.
- `check:code`, `check:docs`, `architecture` (after building the app), and `code-health` passed.
- `vp run ui:verify --story "*button*" --viewport desktop` built Storybook, served and audited 19 stories, logged no cleanup failure, and left no Storybook or Vite process running. One story, `components-button--aligned-at-end`, failed its horizontal overflow check (1445px against 1440px), which this change does not touch.

## Could not verify

- macOS, where the probe uses `kill(-pgid, 0)` instead of `/proc`: the environment is Linux only.

## Did not verify

- App-server targets with `--route`: they need the Compose Postgres service, which this environment does not run. They use the same `stopProcessGroup` as the Storybook server.
- The final SIGKILL for a member forked during a `/proc` scan: the race cannot be reproduced deterministically.
- A zombie group leader with live threads end to end: Node cannot exit only its main thread, so the thread check is unit-tested with injected `/proc` readers.
- A `/proc` listing that fails: it cannot be made to fail in a test without replacing the module, so the fallback is covered by review.

## Dismissed review findings

- Second independent review, stopping a group as soon as its leader exits mid-run: that ends a server whose wrapper hands off to it and exits, which the brief does not ask for. Recording a group that is already empty when its leader exits was kept. The remaining pid-reuse gap is listed as a follow-up on the pull request.
- All other findings were fixed. From the first independent review: pid reuse after the group emptied, a five-second test, a third copy of the stat parser, read errors counted as exited, host-dependent zombie coverage, and a swallowed stop failure after success. From the second: the readiness error hidden by a failed stop, an untested stop after success, untested session, zombie, and read-error rules, a race in the test's `isRunning`, a duplicate liveness probe, and the teardown docs. From CodeRabbit: a member forked during a `/proc` scan, test cleanup when setup fails, a race in the test's `isRunning`, a zombie leader whose threads still run, a `/proc` listing failure that skipped signalling or could escape the exit listener, a final SIGKILL sent when the probe found no group, and a `/proc` test that ran off Linux. From CodeQL: code built from values in the test helper.
