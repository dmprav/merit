# Verification record

## Behavioral decisions

- Create follows the checkout token and Git back-link through bootstrap. It returns the path observed while activating its own registry claim. Losing the claim fails creation and leaves shared resources for the current owner.
- Rollback preserves a live moved checkout, its branch, its database, and the original registry path for move-back recovery. During removal it takes Git’s per-worktree lock exclusively and only overrides its own lock. An existing user lock still prevents removal.

## Checks run

- `vp test tooling/agents/worktree/create-move.test.ts` passed with real temporary Git repositories. On the unmodified base, create left the record in `creating`, rollback dropped the moved checkout’s fake database, and a different attempt’s token was accepted.
- Independent review exposed a stale path when activation waited for the registry lock, an incomplete recovery command, and a move followed by a symlink during removal. The added cases failed before the corresponding fixes and passed afterward. The success case also checks the bootstrap command’s working directory.
- The create and move suites passed together, including rollback of an unmoved, locked, or partially removed checkout. The app build, architecture checks, code-health check, and documentation check passed.
- Automated review identified a move during Git pruning and a missing recovery step for symlinks. A real Git unlock and move during prune reproduced the database drop. The regression verifies the database and registry survive, and recovery instructions cover unlinking the original symlink.
- `vp run test:agents` passed on the review follow-up (630 passed, three skipped).
