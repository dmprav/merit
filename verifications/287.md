# Verification record

## Behavioral decisions

- Every popover (Select, ActionMenu, shell context popover, pickers, reference popovers, Tooltip) uses one surface:
  - `--border-raised`;
  - a new `--popover-radius` of 8px (owner's choice, between controls at 6px and panels at 10px);
  - `--popover-shadow`;
  - a 6px offset from the trigger (the context-menu activation keeps 0);
  - a fade-only enter and exit at `--motion-fast`, instant under reduced motion. Tooltip moves from 10px to 8px, and Select and ActionMenu gain the fade.
- Lists inside popovers use one `.scroller`. Its padding is inside the scrolling list (scrollbar at the surface edge), it has a 19rem max height (cuts a row partway), and a footer edge shows above trailing actions while the list continues. `.surface` sets no z-index, because React Aria's inline z-index wins.
- `--popover-inset` is the row inset inside a scroller. `--popover-gutter` is a padded parent's padding, which dividers bleed through.
- A picker whose content is the list has no padding and one scroll container. A picker with notes or feedback around a list keeps its gutter and scrolls as a whole: the inner list has no height cap, and notes align with row text. The collection toolbar's criteria list also uses the scroller.
- Search palette:
  - rows compose the shared list row;
  - the keyboard bar appears only after ArrowUp, ArrowDown, Home, End, PageUp or PageDown, so the top match at open reads as hover;
  - headings, rows and the field icon share one edge;
  - the field uses the shared focus bar.
- Empty or all-disabled listboxes, and focused menus, show the shared focus bar.
- `ui:verify`'s focus check compares an option or menu item inside an open collection with its focused neighbour (ArrowDown/ArrowUp), because the collection undoes a blur. It reports an incomplete check when focus can't reach a sibling.
- Closing popovers stay in the DOM during their exit fade. Story play functions wait for this with `findByRole` or `waitFor`.
