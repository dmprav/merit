# Explore Merit’s interface

## Choose a pattern for the work

Start with what the person needs to do. Follow the pattern for the design choice
and the feature example to see how it works with grant records.

| Task                                      | What guides the choice                                                                                                                                                                                                                                     | See it in Merit                                                                                                                                                                                                             |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Find and compare records                  | Use a [collection toolbar](?path=/docs/patterns-collection-toolbar--docs) with a [data table](?path=/docs/components-data-table--docs) when the same properties matter across records. A chronological list makes the sequence of events easier to follow. | [Compare applications across rounds](?path=/story/features-applications-all-applications--across-rounds), [Read workspace activity](?path=/story/features-activity-workspace-activity--populated)                           |
| Read evidence while writing               | A [reference workspace](?path=/docs/patterns-reference-workspace--docs) keeps sources within reach and preserves reading position as the author moves between them.                                                                                        | [Write a reviewer assessment](?path=/story/features-applications-review-an-assigned-application--writing), [Read and edit a recommendation](?path=/docs/features-applications-recommendation--docs)                         |
| Edit a property or several related values | Choose the [editing pattern](?path=/docs/patterns-editing--docs) by what commits together. Use a [form dialog](?path=/docs/patterns-form-dialog--docs) for a bounded task.                                                                                 | [Choose a recorded contact](?path=/story/features-applications-manage-intake--edit-recorded-contact), [Edit application details together](?path=/story/features-applications-manage-intake--edit-contact-and-project-dates) |
| Explain or authorize a consequence        | Use [confirmation](?path=/docs/patterns-confirmation-dialog--docs) when the person must decide whether to proceed. Choose [feedback](?path=/docs/patterns-feedback--docs) by what actually happened and what they can do next.                             | [Compare a side effect of changing access with explicit removal](?path=/docs/features-team-design-guidance--docs)                                                                                                           |

## Choose controls by outcome

Start with what activating an item does. Controls with similar popup shapes can
have different navigation, selection, and commitment behavior.

| The person needs to…                                   | Use…                                                                                                                                                               | Keep clear…                                                                      |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| Go to a destination                                    | [Real links](?path=/docs/components-link--docs), with `ApplicationContext` for [workspace switching](?path=/story/patterns-application-shell--workspace-switcher)  | The current destination and normal link behavior, including opening another tab. |
| Choose a value                                         | [Select](?path=/docs/components-select--docs) in a form, or the [editing pattern's choice controls](?path=/docs/patterns-editing--docs) for a property             | The selected value and when the change is committed.                             |
| Run a command                                          | A labeled [Button](?path=/docs/components-button--docs), or [ActionMenu](?path=/docs/components-action-menu--docs) for secondary commands                          | What the command does; keep important actions visible.                           |
| Edit information or inspect focused reference material | The [editing pattern](?path=/docs/patterns-editing--docs), using a [dialog](?path=/docs/components-dialog--docs) when the task needs its own surface               | The task's context, dismissal, and treatment of unfinished work.                 |
| Write a message to send                                | [MessageBox](?path=/docs/patterns-message-box--docs), with the [application shell's companion panel](?path=/docs/patterns-application-shell--docs) beside the page | Sending, stopping, and where the conversation is kept; Enter sends, never saves. |
| Authorize a consequential action                       | [ConfirmationDialog](?path=/docs/patterns-confirmation-dialog--docs)                                                                                               | The consequence, commitment, and recovery if it fails.                           |

Simple destination and value choices use compact rows with visible current or
selected state. Dialog headings, close controls, and content spacing support a
task or reference surface. Choose that framing when the content needs it. If an
existing component cannot preserve the required semantics, extend the owning
shared pattern while keeping the related controls' appearance consistent.
