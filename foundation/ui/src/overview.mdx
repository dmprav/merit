# Choose an interface pattern

Start with the person's task. Foundations establish the visual language;
components supply building blocks; patterns explain recurring interactions and
presentation. Feature stories show these choices in real product work. Guidance
lives with the responsibility it explains, whether or not it needs shared code.

## Choose controls by outcome

Start with what activating an item does. Controls with similar popup shapes can
have different navigation, selection, and commitment behavior.

| The person needs to…                                   | Use…                                                                                                                                                              | Keep clear…                                                                      |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Go to a destination                                    | [Real links](?path=/docs/components-link--docs), with `ApplicationContext` for [workspace switching](?path=/story/patterns-application-shell--workspace-switcher) | The current destination and normal link behavior, including opening another tab. |
| Choose a value                                         | [Select](?path=/docs/components-select--docs) in a form, or the [editing pattern's choice controls](?path=/docs/patterns-editing--docs) for a property            | The selected value and when the change is committed.                             |
| Run a command                                          | A labeled [Button](?path=/docs/components-button--docs), or [ActionMenu](?path=/docs/components-action-menu--docs) for secondary commands                         | What the command does; keep important actions visible.                           |
| Edit information or inspect focused reference material | The [editing pattern](?path=/docs/patterns-editing--docs), using a [dialog](?path=/docs/components-dialog--docs) when the task needs its own surface              | The task's context, dismissal, and treatment of unfinished work.                 |
| Authorize a consequential action                       | [ConfirmationDialog](?path=/docs/patterns-confirmation-dialog--docs)                                                                                              | The consequence, commitment, and recovery if it fails.                           |

Simple destination and value choices use compact rows with visible current or
selected state. Dialog headings, close controls, and content spacing support a
task or reference surface. Choose that framing when the content needs it. If an
existing component cannot preserve the required semantics, extend the owning
shared pattern while keeping the related controls' appearance consistent.
