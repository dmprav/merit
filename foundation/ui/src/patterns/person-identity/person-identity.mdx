# Identify people consistently

Use `PersonIdentity` for a person in property values, lists, attribution, and
account controls. It pairs the visible name with decorative initials; the name
carries the accessible identity. Keep prose mentions and audit sentences as text,
and workspace marks separate from people.

## Fit identity to its context

Compact names use a 24 px avatar, an 8 px gap, and the surrounding typography.
Names with supporting details or an explicit `nameAs` heading use the 28 px form.
Names use regular body weight; use `nameAs` when the name itself introduces a section.
Keep a name and email tightly grouped, with the avatar centered beside both lines.
Use `annotation` for a short identity qualifier such as “You”, beside the name.
Use `status` for an account-level badge beside the name, such as “Account disabled”.
Keep it visibly distinct from muted contact details; the feature supplies its label and tone.
A clear text badge needs no additional warning icon.
Put workflow status, dates, and actions in their own table cells or adjacent content. Supporting content must
be phrasing content, such as text, spans, links, or badges.

## Align and wrap the whole identity

Align the whole avatar/name group with other values. In compact property groups,
use the same 32 px minimum row height for text and people, center content vertically,
and avoid adding a second layer of vertical padding around an identity control.
Let long names wrap and rows grow; keep touch targets at the shared control size.
Supporting content beneath a person aligns with the name using the shared avatar
size and spacing variables. Features arrange the group; avatar dimensions belong
to the shared component, without local overrides.
