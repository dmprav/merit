# Confirm a consequential action

Use confirmation when a person needs to review consequences before committing,
such as removing access or discarding a shared working revision. Routine,
recoverable edits should proceed without confirmation. An explicitly labelled
Discard action in an editor clears only that local draft; Close preserves it.
See the [editing pattern](../editing/editing.mdx) for these distinct actions.

Name the affected person or work, explain what changes, and give the confirmation
button a specific action label. Use destructive intent for removal or loss.
Cancellation receives initial focus so opening the dialog does not commit the action.

## Pending and recovery

Show progress for the confirmed operation, with a label such as “Revoking invitation…”.
Pending prevents confirmation and dismissal. Keep failures visible with a useful
recovery action and preserve enough context to retry.
