# Frame an application

Keep the person's workspace, location, and a useful route back clear as they move
between tasks. Each interface supplies its identity, destinations, and account actions;
the shell owns their shared presentation and responsive navigation.

Use `ApplicationShell` with `ApplicationContext` for the workspace identity above
navigation and `ApplicationAccount` below it. Supply real workspace links containing
`ApplicationContextOption` when switching is available; mark the current link with
`aria-current` to show its selection and checkmark. The compact popup keeps long
names readable and supports Tab navigation, Escape, and outside dismissal. A single
workspace stays static. The interface supplies destinations and account actions
according to the current session.

Place navigation commands, such as opening search, with `ApplicationNavigationButton`,
which shows an optional keyboard shortcut on hover and focus. Use
`ApplicationDocumentationLink` in the footer for documentation that opens in a new
tab, and `ApplicationContextLinks` for workspace links outside the switcher, such as
a page for choosing where to work. Feature stories can use `ApplicationStage` for
the page's scrolling frame without navigation.

Supply translated navigation labels and a current context label for the compact
header. The shell owns the mobile drawer and its focus behavior; `ApplicationPage`
provides the main landmark that receives focus after navigation. Optional utilities,
such as the demo guide, remain accessible in the compact header. The
[shell examples](?path=/story/patterns-application-shell--workspace) show composition,
long names, and account loading. The [open workspace switcher](?path=/story/patterns-application-shell--workspace-switcher)
and [long-name variation](?path=/story/patterns-application-shell--workspace-switcher-long-name)
show the choices in context. Compare their density with the
[action menu](?path=/story/components-action-menu--keyboard) and their selection
cue with the [select](?path=/story/components-select--open), while preserving real
links for workspace navigation.

## Preserve navigation and context

Use meaningful parent destinations in the page's breadcrumb trail. The feature
chooses which context a parent link restores; [breadcrumbs](?path=/docs/components-breadcrumbs--docs)
own the trail's presentation. Pass the current location through `locationKey` so
page navigation can move focus to the main landmark.

Use `breadcrumbAction` for a personal navigation action, such as pinning the
current item to the sidebar. It sits beside the trail, outside the navigation
landmark; record editing and workflow actions belong with the page content.

Use `ApplicationNavigationRow` from `@merit/ui/application-navigation` when a
navigation link has a secondary action: supply the link as its child and a quiet
button or menu trigger as `action`. The [pin examples](?path=/story/features-workspace-pins--pinned)
show this in context, including truncated labels, a full-list popup, and a link
context menu. Use a custom-trigger `Tooltip` for full link text on hover and focus;
retain the complete accessible name and essential context on the destination page.

Wrap reorderable rows directly in `ApplicationNavigationList` and handle `onMove`.
Pointer dragging needs a non-drag path: `ActionMenu` with `activation="contextMenu"`
adds right-click, keyboard, and touch long-press reordering to a real link. Use
`appearance="popup"` on the list within a `PopoverDialog` for a full collection.
The feature owns saved order, hidden items, failure recovery, and focus when a
successful action removes the focused item from the preview.

`ApplicationPage` supplies responsive gutters and standard or full width. The
[page composition pattern](?path=/docs/patterns-page-composition--docs)
explains width, title density, and content hierarchy. Use `contained` for a workspace
whose desktop panes stay within the viewport; its feature owns the pane arrangement.
Compact screens return to document scrolling.

Keep account controls available while account details load. The
[loading account](?path=/story/patterns-application-shell--loading-account) and
[account menu](?path=/story/patterns-application-shell--account-menu) examples show
loading, available actions, and sign-out recovery.

## Keep a companion beside the work

Use the shell's `companion` for a task that runs alongside the page, such as an
assistant, when the person needs to keep reading the page while they use it. Supply a
`label`, which names the panel and is its visible title, whether it is open, and what
closing does. Without a companion, or while it is closed, the shell is unchanged.

<Canvas of={Shell.AssistantPanel} story={{ inline: false, height: "540px" }} />

From 1400 pixels wide the open panel is a labelled region on the right edge. It
scrolls on its own, and the page narrows to make room instead of being covered. Toasts
stay centered on the page. Below 1400 pixels it opens as a modal sheet like a
[side panel](?path=/docs/components-dialog--docs): the page is inert, focus stays inside,
and Escape, the close button, or a click outside closes it. The sheet is 400 pixels wide,
or the full width of a narrower screen. Crossing 1400 pixels while it is open changes
the presentation and keeps it open.

In the pushed presentation a separator on the panel's left edge resizes it between 400
and 560 pixels, starting at `width` (416 by default). Dragging, or the arrow keys on the focused
separator (16 pixels a step, Home and End for the limits), reports each committed width
through `onWidthChange`. Pointer dragging has a non-drag path: pressing the separator
without dragging toggles between the default 416 pixels and the 560 widest. The shell does not save it; the caller decides whether to.

<Canvas of={Shell.AssistantPanelWidest} story={{ inline: false, height: "540px" }} />

Opening moves focus into the panel: to the element the caller gives `autoFocus`, otherwise to
the panel itself. Closing from inside the panel returns focus to the control that opened it,
or to the main content when that control is gone. When the caller closes the pushed panel
while focus is elsewhere on the page, such as from a shortcut, focus stays where it is. Escape inside the pushed panel closes it unless a menu or
popup inside has already used it. The panel's content mounts only while it is open, and again
when the screen crosses 1400 pixels, so keep drafts and history with the caller.
Compose a conversation from a [message box](?path=/docs/patterns-message-box--docs).

The panel's body scrolls its content under the header, whose divider appears once it does.
Give `footer` what must stay in view however far the content scrolls, such as the message
box; it sits below the body in both presentations and mounts with the content.

## Recover within the available frame

Keep usable navigation when a page fails inside an accessible workspace. Use
`ApplicationRecovery` when the whole workspace is inaccessible, supplying account
controls and a useful return link. The [feedback pattern](?path=/docs/patterns-feedback--docs)
explains placement and recovery behavior; the interface determines accessible destinations.
