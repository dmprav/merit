# Label fields and explain validation

Shared text fields, date fields, and selects keep labels, requirements, and feedback
consistent. Choose the control for the value and use `@merit/forms` when connecting
it to a form's validation and submission. Features supply localized labels, errors,
and validation; the owning workflow determines what the action requires.

## Choose the right field state

Use a [description list](?path=/docs/components-description-list--docs) for fixed
facts on a reading surface. Inside an editor, use a read-only text field when a
value is fixed by permissions: retain the field's label, alignment, and readable
value, and explain the restriction. Read-only fields support focus and copying,
but retain their muted surface and use a quiet dashed focus outline instead of
the editable field's active underline. They never expose a dropdown arrow.

Explain unfamiliar choices where people compare them. Select options can carry
short descriptions, while the closed control shows only the selected label.
Use field-level help for guidance applying to the whole choice, rather than
repeating the selected option's description beneath the control.

Use disabled controls for unavailable interaction. Explain restrictions when their
reason is unclear and offer a remedy when missing data blocks progress.

Use `isRequired` for input needed by the current action. Editable required fields
show accessible semantics and a quiet **Required** label, including after the
person fills the field. Read-only and disabled fields omit the visible marker;
the underlying requirement still applies. Leave optional fields unmarked.

## Keep feedback beside the field

Give empty or malformed values specific corrective messages and preserve entries
after an unsuccessful save. Keep forms focused on labels, values, and corrective
feedback; broader explanations belong in user guides. Add inline explanation when
it helps the person understand the current action.

Field labels use control typography at medium weight; requirements and feedback
use caption text. Field parts use `space-1` gaps. Errors replace helper text in a
shared feedback area, retaining the helper's height so short errors do not shift
the following control. Longer errors grow and wrap, including unbroken addresses
and identifiers. Fields without feedback leave no empty row.

## Allow content to grow

Multiline text fields default to five rows and a 120 px minimum, with vertical
resizing and 8 px vertical padding. Labels, values, and feedback wrap or grow with
long content and enlarged text. Shared [density and focus conventions](?path=/docs/foundations-tokens--docs)
keep field states consistent with the surrounding controls.
