# Layout primitives

Use these building blocks for recurring flow and line length inside a component.
The [design language guide](?path=/docs/design-language--docs) explains the
spacing scale. [Page composition](?path=/docs/patterns-page-composition--docs)
explains page framing and arrangements for reading, comparison, and editing.

## Compose simple flows

Import `Stack` and `Inline` from `@merit/ui/layout`. `Stack` arranges direct children
vertically; `Inline` wraps them in reading order as the available space allows,
including in a narrow panel on a wide screen. Set `gap` to a step in the spacing
scale when a group needs a different rhythm, or `gap="section"` on a `Stack` of
consecutive page or pane sections, which spaces them with `--space-section`.

Choose an appropriate element with `as`: label sections, preserve article semantics,
and supply `li` children for lists. These components add no headings or landmarks
automatically. Keep DOM order meaningful for reading and keyboard navigation.
Put feature presentation, such as columns, unequal
row and column gaps, borders, container queries, and breakpoint-dependent changes,
on the feature's own element around or within the flow.

<Canvas of={Layout.Narrow} story={{ inline: true, height: "480px" }} />

Use `align="start"` when a short action should sit at the top of multiline content,
`align="end"` when controls should share the bottom edge of fields beside them,
and `align="baseline"` when differently sized text should share a baseline.
Use `justify="between"` to separate context from its action while they fit on one
line; a wrapped item starts a new line in reading order. Use `justify="end"` for
an action group aligned to the end of its available space. Alignment applies to
each line, so check the wrapped result as well as the wide arrangement.

## Rule off entries

Set `divided` on `Stack` to separate entries with rules instead of drawing borders in
feature CSS: `between` centres a subtle rule in each gap. Use
[Divider](?path=/docs/components-divider--docs) for a single rule between blocks.

<Canvas of={Layout.DividedEntries} />

## Constrain reading

Use `Reading` to constrain prose, such as a submission answer or a reason, inside a
page or panel. Constrain the prose itself so surrounding actions, comparison
columns, and tables can use their available width. Set `prose={false}` for a short
reason in a compact summary that should keep the surrounding size.
