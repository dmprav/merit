# Design language

Merit uses the same visual cues across grant work. Use this guide when choosing
what should stand out, how much space information needs, or how a control shows
that someone can act. Switch between the product and site themes to see how
the colors change while their meanings carry across surfaces.

## Emphasis and meaning

**Give the strongest emphasis to the distinction that changes the person's next action.**
A manager's recommendation to fund is a judgment. Give the position a clear
label and keep it beside its author. A selected application needs a visible
selection cue. A successful save needs a confirmation. These can appear on the
same screen, so each needs its own meaning.

<Canvas of={Language.SemanticColors} />

The samples pair text and surface tokens. Use ordinary text and grouping for
facts, the action color for interactive emphasis, and outcome colors for
success, warning, or failure. Pair each color with words or another visible cue.
The [feedback pattern](?path=/docs/patterns-feedback--docs) shows how to present
the result beside the work it affects. Theme maintainers can find both palettes
in the [token definitions](https://github.com/dmprav/merit/blob/main/foundation/ui/src/foundations/tokens.css).

## Reading and layout

**Give sustained reading a comfortable line length and give comparable values a common edge.**
In the example, the submission version sits close to the applicant's words. The
budget has more space above it because the reader is switching from understanding
a proposal to comparing its costs.

<Canvas of={Language.ReadingAndComparison} />

Use `Reading` for submissions, assessments, and reasoning. Use compact detail text for comparable facts and tabular numerals for amounts.
Keep labels beside values as the available width changes.

Use the [layout primitives](?path=/docs/components-layout-primitives--docs) to
group related items on the shared spacing scale. Here, `gap={2}` connects the
source to its passage and `gap={6}` separates the budget. Let a dense queue
keep its compact controls while leaving room for touch targets, longer translations,
and enlarged text. The [page composition guide](?path=/docs/patterns-page-composition--docs)
applies these choices to whole screens.

## Typeface

**Use one typeface and let size and weight carry the hierarchy.** Merit sets all
interface and reading text in Instrument Sans, through `--font-sans`, so the
product looks the same on every platform. It stays even at the 12–13px sizes
used for captions and detail text. Emphasize with weight 500 or 600, not italics.
Use tabular numerals for amounts and counts so columns line up.

The package `@fontsource-variable/instrument-sans` serves the font from Merit
itself. Platform fonts remain in the stack as the fallback while it loads.
Emails keep platform fonts, because mail clients do not load web fonts reliably.

## Interaction cues

**Keep focus visible alongside the control's existing state.** Tab through the
comparison. An editable field marks where typing will go. An invalid field keeps
its error treatment while focused. A read-only value can still receive focus
for copying, and Tab skips disabled controls. Selection marks the current
choice even as keyboard focus moves on.

<Canvas of={Language.FocusComparison} story={{ inline: false, height: "540px", autoplay: false }} />

[Open the focus comparison on its own](?path=/story/design-language--focus-comparison)
to try keyboard and pointer input in either theme. Focus indicators should stay
visible without moving the surrounding content. In forced-colors mode, controls
use system outlines so the indicator survives changes to fills and shadows.

Motion helps someone follow a surface as it opens or closes. Keep input available
during entry, and respect the device's reduced-motion preference by skipping
the transition. [Open and close a dialog](?path=/story/components-dialog--centered-with-actions)
to see the preference in use. Focus placement and return belong to the
[dialog's interaction contract](?path=/docs/components-dialog--docs).
